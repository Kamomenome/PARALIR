# Feature Specification: 絵の縦横比は写真のまま（版 1.33 に含める）

**Feature Branch**: `018-photo-aspect`
**Created**: 2026-10-13
**Status**: Draft
**Input**: 利用者「あと写真の縦横比が固定になるのクソだな　オリジナルを踏襲しろ」。言葉は [docs/GLOSSARY.md](../../docs/GLOSSARY.md)（縦横比）。

## 調べたこと

- プレビューは 960×720、書き出しは 2400×1800 に固定（4:3）。どの世界も写真を 4:3 の枠いっぱいに合わせ、はみ出す所を切り落としていた（`frameOf`）
- 描き方は出力の大きさ W×H を受け取るだけなので、W×H を写真の縦横比にすれば、描き方を変えずに切り落としがなくなる（版上げ・凍結は要らない）

## Requirements *(mandatory)*

- **FR-1801**: 絵の縦横比を写真と同じにする。書き出しは長い辺を 2400px（例 3:2 の横長 → 2400×1600、縦長 → 1600×2400）、プレビューは長い辺を 960px
- **FR-1802**: 絵の場所の枠も写真の縦横比にする（写真を入れる前は 4:3）。元の写真の表示も切り落とさない
- **FR-1803**: 書き出しのボタンの大きさの表示を、実際の大きさにする（例「画像を書き出す（2400×1600）」）
- **FR-1804**: レシピに書き出しの大きさを書く（今までどおり `output.width`・`output.height`）。レシピを読み込んだら、その大きさの縦横比で描く（今までのレシピは 2400×1800 で、今までの絵のまま）
- **FR-1805**: 描き方は変えない（同じ大きさなら同じ絵。画素の記録は変わらない）

## Success Criteria *(mandatory)*

- **SC-1801**: unit: 縦横比から大きさ（横長・縦長・正方形）。写真を入れると書き出しの大きさが写真の縦横比、レシピを読むとレシピの大きさ。レシピに大きさが書かれる
- **SC-1802**: e2e: 3:2 の写真で、プレビューが 960×640、元の写真の四隅が切れていない、書き出しのボタンが（2400×1600）、書き出した PNG が 2400×1600。2400×1800 のレシピを読むと（2400×1800）
- **SC-1803**: 既存のテストと画素の記録がすべて通る
