# 性能測定（T081 / SC-011）

`npx playwright test tests/e2e/perf.spec.ts`（結果は `out/perf.json`）。目標値は docs/SPEC.md §7 の**仮の目標**。

## 測定環境

| 項目 | 値 |
|---|---|
| 日付 | 2026-10-11 |
| CPU | Intel Core i7-14700F（論理 28 コア） |
| メモリ | 32 GiB |
| OS | Windows 11 Home 10.0.26300 |
| ブラウザ | Playwright Chromium 153.0.8010.12（開発サーバー経由） |
| 描画 Worker 数 | 27（論理コア数 − 1） |
| 入力 | `docs/reference/source.jpeg`（1206×915）、world-v3、既定の操作値 |

## 結果

| 測定 | サンプル（ms） | 中央値 | 仮目標 | 判定 |
|---|---|---|---|---|
| 960×720 プレビュー（スライダー操作から描画完了まで、再構成を含む） | 283, 215, 242, 253, 208, 264, 200 | **242 ms** | 250 ms | 中央値は達成。7 回中 3 回は超過 |
| 2400×1800 書き出し（ボタンから PNG 保存まで） | 1005, 1026, 1016 | **1016 ms** | 10 秒 | 達成 |

## Phase 10 後（高品質書き出し 3×3 が既定）

| 測定 | サンプル（ms） | 中央値 |
|---|---|---|
| 960×720 プレビュー（標準、1 点/画素） | 588, 418, 303, 227, 228, 258, 247 | 258 ms（初回は起動直後） |
| 2400×1800 書き出し（高品質 3×3） | 6558, 6436, 6420 | **6.4 秒**（仮目標 10 秒以内。標準品質は約 1.0 秒） |

利用者の方針（速さより画質）により、書き出しの既定を高品質にした。

## 行った高速化（T082）

- プレビューの行帯を `max(8, ceil(720 / (Worker 数 × 2)))` 行に細分化し、全 Worker に仕事が行き渡るようにした。
  変更前（64 行固定）は中央値 294 ms。描画結果は行帯の分け方に依存しない（`tests/integration/determinism.test.ts`、
  `tests/unit/controller.test.ts`）。

## 注意

- 測定機は 28 論理コアの高性能 CPU。一般的な 4〜8 コアの PC ではプレビューが数倍遅くなる見込みで、仮目標を超える可能性が高い。
  対象の利用者環境での測定は未実施。
- 単一 HTML を `file://` で開いた場合も並列 Worker で動作することを確認済み（`tests/e2e/build-file.spec.ts`）。
  Worker が起動しない環境では画面の処理の中で描画する代替策に切り替わり、大幅に遅くなる（通知を表示）。
- JS 版 reference-v1 の 2400×1800 描画は単一スレッドの Node で 3.3 秒（`reference-verification.md`）。
