## User Scenarios & Testing *(mandatory)*

### User Story 1 - 写真から変貌世界を生成し、同じ条件で呼び戻す (Priority: P1)

利用者は写真を1枚読み込む。アプリは作品日時（初期値は開始時の現在日時）と別案番号から構成を決め、
元写真の部品が分かる大きな断片・形が崩れた中くらいの断片・意味が読めない細かな模様が一枚に
混ざった「変貌世界」をプレビュー表示する。同じ写真・日時・別案番号・設定なら、何度生成しても
同じ画像になる。写真の色構成・明暗・輪郭の違いは、構成の選ばれ方と変形に表れる。

**Why this priority**: アプリの存在理由そのもの。これだけで「写真を変貌させて作品を得る」価値が成立する。

**Independent Test**: 任意の写真を読み込み、固定した日時・別案番号で2回生成して画素一致を確認し、
粗・中・細の診断マスクと完成画像を出して、粗い部分が元写真のどの部品か対応付けられることを確認する。

**Acceptance Scenarios**:

1. **Given** JPEG または PNG の写真が1枚ある, **When** 利用者がそれを読み込む, **Then** EXIF の向きどおりに正立し、透過部分は白で合成され、その旨が画面に表示されたうえで変貌世界のプレビューが表示される（R01）
2. **Given** 同じ写真・日時・タイムゾーン・別案番号・設定・エンジン版, **When** 2回生成する, **Then** 2つの結果は画素単位で一致する（A02）
3. **Given** 生成結果, **When** 診断表示を開く, **Then** 粗・中・細それぞれの領域マスクと、粗い断片が元写真のどの位置から切り出されたかが確認できる（R06, A07）
4. **Given** seed を固定する, **When** 「画像特徴の影響」を 0 と 1 で比較する, **Then** 画像解析に由来する変形の差が確認できる（A05）
5. **Given** 平均色とヒストグラムが同じで画素配置だけが異なる2枚の画像, **When** 同じ日時・別案番号で生成する, **Then** 局所的な変形が異なる（A06）

---

### User Story 2 - 承認済み基準画像を再現する (Priority: P2)

利用者（制作者）は基準再現モードを選び、基準の元写真から、乱数を使わない承認済みの
変換（reference-v1）で 2400×1800 の画像を再現し、承認済み画像と完全に一致することを確認できる。

**Why this priority**: 乱数構成（world-v3）の中層・細層は基準の数値変換を土台にするため、
その正しさを固定しておく必要がある。参照ファイルの配置待ちのため P2 とするが、参照ファイルが
届き次第、開発上は最初に検証する。

**Independent Test**: 同梱の検証手順で承認済み画像との RGB 完全一致を（作成環境同等の数値環境で）確認し、
アプリの基準再現モードでは承認済み画像との誤差を測定して暫定目標内であることを確認する。

**Acceptance Scenarios**:

1. **Given** 参照ファイル一式（元写真・承認画像・元コード・検証手順）が配置されている, **When** 元コードを変更せずに同梱の検証を実行する, **Then** 承認済み画像とデコード後RGBが完全一致する（A01）
2. **Given** アプリの基準再現モード, **When** 基準の元写真で 2400×1800 を書き出す, **Then** 承認済み画像との 8bit 誤差（平均・p99・最大）が報告され、暫定目標（平均≤1・p99≤3）を満たす（R02）。同一環境での2回の実行は完全一致する
3. **Given** 基準再現モード以外, **When** 任意の写真を読み込む, **Then** 基準写真専用の上下の縁の切り落としは適用されない

### User Story 3 - 別の世界を探し、調整する (Priority: P3)

利用者は「別の世界」で同じ写真・日時のまま別案を次々に作り、日時やタイムゾーンを変えて
構成を変え、スライダーで粒度・ばらつき・形を残す割合・変形・色の変容・画像特徴の影響を
調整する。スライダー操作では構成の配置は保たれ、強さだけが変わる。元画像と比較したり、
構成をリセットしたり、直前のレシピへ戻したりできる。

**Why this priority**: 1枚の生成ができた後、作品として選び込むための操作。

**Independent Test**: 同じ写真で「別の世界」を押すと構成が変わり、スライダー操作では配置が
保たれたまま見た目の強さだけが変わることを確認する。

**Acceptance Scenarios**:

1. **Given** 生成済みの作品, **When** 「別の世界」を押す, **Then** 別案番号が1増え、写真と日時は固定のまま新しい構成になる（R04）
2. **Given** 生成済みの作品, **When** 日時または別案番号を変える, **Then** 構成が変わり、その変化は一様な色相変更だけに終わらない（R03, A04）
3. **Given** 生成済みの作品, **When** 「形を残す割合」を上げる, **Then** 粗い断片の面積が増え、それはぼかしや低解像度化ではない（R07, A08）
4. **Given** 任意のスライダー, **When** 値を変える, **Then** 構成の配置（どこを切り出しどこに置くか）は保たれる
5. **Given** 作品日時の入力, **When** 「現在に合わせる」を押す, **Then** 作品日時が現在時刻に更新される。押さない限り作品日時は固定される
6. **Given** 存在しない・または二通りに解釈できるローカル時刻, **When** それを入力する, **Then** 解決後の日時とオフセットが画面に表示される
7. **Given** 調整中の作品, **When** 元画像比較・構成のリセット・直前のレシピ復元を使う, **Then** それぞれ期待どおりに動作する（R08）
8. **Given** 描画中に利用者が続けて操作した, **When** 古い描画が後から終わる, **Then** 古い結果は表示されず、最新の操作が反映される。描画が失敗しても設定は失われない（R12）

---

### User Story 4 - 高解像度で書き出し、レシピで保存・復元する (Priority: P4)

利用者は気に入った作品を 2400×1800 の PNG として書き出し、作品を再現するためのレシピを
ファイルに保存できる。後日、同じ写真とレシピを読み込むと同じ作品を書き出せる。

**Why this priority**: 作品を残し、後から呼び戻せるようにするための仕上げ。

**Independent Test**: レシピを保存し、アプリを開き直して同じ写真とレシピを読み込み、
書き出し結果が元の書き出しと画素一致することを確認する。

**Acceptance Scenarios**:

1. **Given** 調整済みの作品, **When** 書き出しを開始する, **Then** 開始時点の写真・日時・設定が固定され、その後の操作は書き出し結果に影響しない。書き出しはキャンセルできる（R11）
2. **Given** プレビュー（縮小）と書き出し（2400×1800）, **When** 同じ作品を描画する, **Then** 正規化座標上の構成・マスク・サンプル位置が一致する（R09, A09）
3. **Given** 保存したレシピと同じ写真, **When** 読み込んで書き出す, **Then** 元の書き出しと画素一致する（R10, A10）
4. **Given** レシピと異なる写真, **When** そのレシピを読み込む, **Then** 同一作品の再現とは扱わず、その旨を表示する
5. **Given** 未知の版・不正な数値・非整数の反復数・NaN/Infinity を含むレシピ, **When** 読み込む, **Then** 読み込みを拒否し、理由を表示する

---

### User Story 5 - 見た目を比較してプリセットを決める (Priority: P5)

利用者は同じ写真・日時について、少数の別案と粗い領域の比率違いを並べて見比べ、
美しさ・部品の読める度合い・粒度差を評価し、採用する係数・比率をプリセットとして決める。

**Why this priority**: 係数や粒度比率は未評価の設計案であり、数値上の合格とは別に見た目の合格が必要。

**Independent Test**: 比較用の画像一式を出力し、利用者が選んだ値がプリセットとして記録されることを確認する。

**Acceptance Scenarios**:

1. **Given** 1枚の写真と固定日時, **When** 比較画像の生成を行う, **Then** seed 違い数案と粗い領域比率違い数案が並んだ比較画像が得られ、見た目の調整点が明示される（A12）
2. **Given** 比較結果, **When** 利用者が採用案を選ぶ, **Then** その値がプリセットとして固定・記録される。利用者が選ぶまでは「未評価」と表示される

---

### Edge Cases

- 無彩色・真っ黒・真っ白・単色・ごく小さい画像でも、計算が破綻（NaN 等）せず、未処理のエラーで止まらない（A11）
- 壊れたファイル、JPEG/PNG 以外の形式、サイズ上限（仮: 20MiB または 1200万画素）を超える画像は、理由を示して読み込みを拒否する
- 透過 PNG は白で合成し、その挙動を画面に明示する
- 粒度のばらつきが 0 のときや、粒度場に同じ値が多いときも、ゼロ除算せず定められた規則で層を割り当てる（docs/SPEC.md §5.3）
- 夏時間の切替などで存在しない・二義的なローカル時刻は、解決結果を表示する
- タイムゾーン定義が後で更新されても、保存済みレシピの seed 入力は黙って変わらない
- ファイル名やメタデータだけが違い画素が同じ写真は、同じ構成になる
- 書き出し中のキャンセル、描画中の連続操作、描画失敗のいずれでも設定は失われない

> **改訂（2026-10-12、spec 002 FR-223）**: 入力の画素数上限（1200 万画素、docs/SPEC.md の仮の制約）は、5000 万画素以下なら拒否せず、
> 読み込み後に決定的な面積平均で 1200 万画素以下へ縮小して使う形に改めた（iPhone の標準写真が拒否されていたため）。縮小後の画素が画素ハッシュの入力になる。
> 以前は拒否していた大きさの写真だけが対象なので、既存の作品・レシピの結果は変わらない。

## Requirements *(mandatory)*

### Functional Requirements

**入力**

- **FR-001**: システムは JPEG/PNG 画像を1枚読み込み、EXIF の向きに従って正立させ、透過部分を白で合成し、サイズ上限を検査しなければならない（R01）
- **FR-002**: 画像処理はすべて利用者の端末内で行い、画像を外部へ送信してはならない

**基準再現（reference-v1）**

- **FR-003**: システムは乱数を使わない基準再現モードを持ち、基準の元写真から 2400×1800 画像を生成し、承認済み画像との 8bit 誤差（平均・p99・最大・誤差>3 の画素率）を報告しなければならない（R02）。暫定目標は平均 1 以下・p99 3 以下で、未達のとき閾値を緩めず原因を調べる。数値手順は docs/REFERENCE_METHOD.md §4 に従う。承認済み画像との完全一致（A01）は同梱 Python を作成環境と同等の数値環境で実行して確認する（research.md R-05）
- **FR-004**: 基準写真専用の縁の切り落とし（上5px・下6px）は基準再現モードだけに適用し、一般画像の初期値は四辺 0px としなければならない

**seed と再現性（world-v3）**

- **FR-005**: システムは画素内容・作品日時（瞬間・ローカル日時・タイムゾーン・オフセット）・別案番号から構成用の seed を決定的に導出しなければならない（R03）。導出の契約は docs/SPEC.md §3.2 に従う
- **FR-006**: seed は画素内容から求め、ファイル名やメタデータだけの違いでは変わってはならない
- **FR-007**: 構成に使う乱数は用途（配置・切出し・変形・色・粒度）ごとに独立した系列とし、ある用途の追加・変更が他の用途の系列に影響してはならない（A03）。契約は docs/SPEC.md §3.3 に従う
- **FR-008**: 出力解像度・処理順・分割数によって乱数の消費位置が変わってはならない
- **FR-009**: 同じ画素・日時・別案番号・設定・エンジン版からは、同じ結果を生成しなければならない（A02）

**画像特徴の反映**

- **FR-010**: システムは画像全体の明るさ・コントラスト・彩度・色相分布・明度エントロピー・輪郭量と、局所的な明るさ・彩度・勾配を解析しなければならない（R05）。計算定義は docs/SPEC.md §4 に従う
- **FR-011**: 解析結果は seed に含めるだけでなく、乱数の範囲・分布・選択確率と局所変形へ反映しなければならない（R05, A05, A06）
- **FR-012**: 解析は出力解像度から独立した固定の解析サイズで行わなければならない

**粒度の混在**

- **FR-013**: システムは、部品が分かる粗い断片（粗C）・痕跡が読める中くらいの変形（中M）・意味が読めない細かな模様（細F）を一枚の中に混在させなければならない（R06）。描画方式は docs/SPEC.md §5.1〜5.2 に従う
- **FR-014**: 粒度の配置は一画素ごとに独立に決めず、大きなまとまりを持つ場から決め、境界だけをなじませなければならない（docs/SPEC.md §5.3）
- **FR-015**: 粗い断片では元写真の部品の形を保ち、ぼかし・低解像度化・モザイク化で粒度を代替してはならない
- **FR-016**: 画素は元写真のサンプリングと色計算から作り、全画素を独立した乱数で置き換えてはならない
- **FR-017**: 角度方向の反復数は常に整数でなければならない

**操作**

- **FR-018**: 利用者は作品日時とタイムゾーンを指定できなければならない。初期値は開始時の現在日時と端末のタイムゾーンとし、その後は「現在に合わせる」を押すまで固定する
- **FR-019**: 「別の世界」は別案番号を1増やし、写真と日時を保ったまま新しい構成を作らなければならない（R04）
- **FR-020**: 利用者は分解の細かさ・粒度のばらつき・形を残す割合・変形の強さ・色の変容・画像特徴の影響を操作できなければならない（R07）
- **FR-021**: スライダー操作では構成の seed を変えず、日時・別案番号・元画像を変えたときだけ構成を変えなければならない
- **FR-022**: 利用者は元画像との比較、構成のリセット、直前のレシピの復元ができなければならない（R08）。「直前のレシピの復元」は、「別の世界」・日時・タイムゾーンの変更で構成 seed が変わる直前の状態（seed 入力と操作値）へ1段戻す操作とする。「構成のリセット」は seed を保ったまま操作値をプリセットの既定値へ戻す操作とする
- **FR-023**: 描画中に新しい操作があれば古い描画結果を破棄し、描画が失敗しても設定を失ってはならない（R12）
- **FR-024**: 粗・中・細の診断マスクと、粗い断片の切り出し元を確認できる診断表示を提供しなければならない（A07）

**書き出しとレシピ**

- **FR-025**: 縮小プレビューと 2400×1800 PNG 書き出しは同じ構成・同じ描画規則を使い、プレビュー画像の拡大で書き出しを作ってはならない（R09, A09）
- **FR-026**: 書き出しは開始時の写真・日時・設定を固定し、キャンセル可能でなければならない（R11）
- **FR-027**: 利用者は版付きのレシピを保存・読み込みできなければならない（R10）。保存内容は docs/SPEC.md §8 に従う。レシピは world-v3 の作品が対象で、基準再現モードではレシピを保存しない（基準の設定は同梱の docs/presets/approved-v1.json で固定されているため）
- **FR-028**: レシピ読み込み時は写真と各入力から seed と解析値を再計算して整合性を検証し、画素が一致しない写真では同一作品の再現と扱ってはならない
- **FR-029**: 未知の版・不正な数値・非整数の反復数・NaN/Infinity を含むレシピは拒否し、旧版を新しい規則で黙って描画してはならない

**評価**

- **FR-030**: 同じ写真・日時について、seed 違いと粗い領域比率違いの比較画像を出力できなければならない（A12）
- **FR-031**: 係数・粒度比率は利用者が比較結果から選ぶまで「未評価」として扱い、選ばれた値をプリセットとして記録しなければならない

### Key Entities *(include if feature involves data)*

- **入力画像**: 利用者が読み込んだ写真。元ファイルのハッシュ、正立・白合成後の画素のハッシュ（pixelHash）、寸法、前処理設定を持つ
- **作品日時スナップショット**: seed に使う日時。瞬間（UTCミリ秒）、ローカル日時、タイムゾーン、解決済みオフセットを持つ
- **構成 seed**: 入力画像・作品日時・別案番号・エンジン版から導出される根の seed と、用途別の乱数系列
- **画像特徴**: 全体統計（明るさ・コントラスト・彩度・色相分布・エントロピー・輪郭量）と局所マップ。解析版を持つ
- **構成**: 粒度マスク（粗・中・細）、粗い断片の切り出し元と配置、変形・色のパラメーター。出力解像度に依存しない
- **操作値**: 各スライダーの値と粒度比率。構成 seed を変えずに強さを変える
- **レシピ**: 作品を再現するための版付き記録。入力画像の識別情報、日時スナップショット、別案番号、seed、操作値、各アルゴリズムの版、解析値、出力サイズ・品質モードを含む
- **描画ジョブ**: プレビューまたは書き出しの1回分。開始時の入力を固定し、最新かどうか・キャンセル状態を持つ
- **プリセット**: 利用者が比較から選んで採用した係数・粒度比率。評価状態（未評価/採用）を持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 同梱 Python を作成環境と同等の数値環境で実行した結果が承認済み画像と不一致 0 画素（A01）。アプリの基準再現モードは承認済み画像との 8bit 誤差が平均 1 以下・p99 3 以下（暫定目標）で、誤差値を報告する（R02）
- **SC-002**: 同じ入力・設定で2回生成した結果の不一致画素が 0 である（A02）
- **SC-003**: 固定 seed から得られる乱数列が、検証用の固定値と先頭から一致し、用途を追加しても既存用途の系列が1つも変わらない（A03）
- **SC-004**: 日時または別案番号の変更で構成が変わり、変更前後の比較で配置・粒度マスクが異なる（A04）
- **SC-005**: 「画像特徴の影響」0/1 の比較、および画素配置だけが違う2画像の比較で、それぞれ局所変形に差が出る（A05, A06）
- **SC-006**: 「形を残す割合」を上げると粗い断片の面積比が単調に増える（A08）
- **SC-007**: プレビュー解像度と書き出し解像度で、同じ正規化座標の構成・マスク・サンプル位置が一致する（A09）
- **SC-008**: レシピ保存→同じ写真とともに復元→書き出しの結果が、元の書き出しと不一致 0 画素（A10）
- **SC-009**: 無彩色・黒・白・単色・小画像・壊れた入力の各試験で、NaN の発生と未処理のエラーが 0 件（A11）
- **SC-010**: 利用者が比較画像を見て、美しさ・部品の読める度合い・粒度差を評価し、採用するプリセットを選べる（A12）
- **SC-011**: 960px 幅のプレビュー更新が 0.25 秒以内、2400×1800 の書き出しが 10 秒以内（いずれも仮目標。対象環境で実測し、測定環境とともに報告する）

## Assumptions

- 対象は Windows 11 上のデスクトップ版 Chromium 系ブラウザ（Microsoft Edge / Google Chrome）で、画像処理は端末内のみで完結する（憲法 原則III）。他のブラウザは本 MVP の対象外
- 参照資料一式は `docs/` に配置済み（`docs/reference/` に元写真・承認済み画像・元 Python コード・検証手順・依存定義。`docs/check_bundle.py` で全16ファイルのハッシュ一致を確認済み）
- 2026-10-11、Windows 11 上の Python 3.12.15 + 記載の依存版で元コードを実行した結果、承認済み画像と完全一致しなかった（最大誤差 1、平均絶対誤差 0.0022 / 8bit）。JPEG デコード結果は作成環境の `decoded-source.png` と一致しており、差は浮動小数点計算の環境差によると推定する。作成環境（Linux）と同等の環境で一致を確認するまで A01 は未達とし、合格とは記録しない
- 基準再現の検証には、参照資料に記載の Python 環境（3.12 系と記載の依存版）を用いる
- 入力上限（20MiB / 1200万画素）と性能目標（SC-011）は仮の値であり、実測後に見直す
- 粗中細の初期面積比（40/35/25%）、粗い断片の幅（画面幅の 10〜35%）、各係数は未評価の初期案であり、User Story 5 の比較で調整してから固定する
- 色管理は基準の RGB 契約（ICC 変換なし）から始め、変更する場合は版を上げる
- 高周波のエイリアシング対策は、基準モードとは別の品質モードとして扱う
- 連続アニメーション・動画、公開・アカウント・クラウド保存・SNS 連携は本 MVP の範囲外
- 日時の日内・年内位置を色や変形の弱い傾向に使うことは任意の追加案であり、必須ではない
