# 008 の評価と決定の記録

## 2026-10-13 3 つの観点での点検（ver 1.25、読むだけ）

調査役を 3 つ並行して走らせ、重い指摘はコードで裏を取った。

### セキュリティ
- 写真が外へ出る経路は見つからない。ただし遮断は window の fetch・XHR・sendBeacon の差し替え 1 枚だけで、CSP がない（→ FR-812）
- 入れ子がとても深いレシピで、読み込みが黙って失敗する（20 万段で再現）（→ FR-814）
- 写真を丸ごと読んでから大きさを確かめている。読み込み後の幅と高さを確かめ直していない（→ FR-813）
- 絵の枠の外へのドロップで、ブラウザがファイルを開いて作業が消える（007 の続き）（→ FR-815）
- AI モデルのハッシュはダウンロード時だけ確かめている（低。今回は見送り）
- 問題なし: innerHTML などはない、プロトタイプ汚染は効かない、レシピの値の検証、SVG などは先頭バイトで断る、書き出しのファイル名、描画用 Worker に通信のコードはない
- npm audit: high 4 件はすべてビルド用の依存。source-map-js は上げて直す（→ FR-819）。braces（vite-plugin-singlefile 経由）は直った版待ち

### 堅牢性
- 写真を全 Worker（CPU の数 − 1）にコピーし、各 Worker が Float32 の版も持つ。16 スレッドで最大 2.7GB ほど（見積もり）。描画は 1 枚まるごとなので Worker を増やしても速くならない（→ FR-804）
- Worker が落ちたときの処理がなく、Worker が減り続けて 0 になると止まる（→ FR-805）
- 写真を替えた直後に「source N is not loaded」で失敗する。続けて 2 枚選ぶと先の写真が残ることがある（→ FR-809, FR-810）
- AI に時間の上限がなく、返らないと全操作が止まる（→ FR-807）。「失敗した結果を覚えたまま」という指摘は誤り（`src/ai/parts.ts:40` で失敗時は捨てている）
- 書き出しが取り消し済みのプレビューに押されて始まらないことがある（→ FR-804）
- 囲みの操作の扱い（→ FR-816）、レシピ読み込みの順番（→ FR-811）、準備の失敗（→ FR-808）

### アーキテクチャ
- 7 つの世界の絵が画素で固定されておらず、変わっても気づけない（→ FR-801）
- 版を 1 つ上げると、すべての保存レシピが読めなくなり、どの版で開けばよいかも分からない（→ FR-802, FR-803）
- 「凍結」のはずの Phase 9（`p9/composite.ts`）が今の `atmosphere.ts` の光の形を使う。FR-801 の記録（主題）で変化に気づけるようにする
- 消したモードの残り（qualityMode、world-v3 の seed、使われない描画、古い文書）（→ FR-817, FR-818）
- 良い点: core は画面に依存しない、状態の変化は新しいオブジェクトを返す関数、レシピの検証が厳格

## 決定

- 提案した順（再現の守り → Worker とメモリ → 写真を替えたときの順番 → セキュリティ → 片付け）で全部進める（利用者「OK」、2026-10-13）
- **版の照合は世界ごとに絞らない（FR-803）**: 世界ごとにすると「その世界がどの共通部品に頼っているか」の表を人が保つことになり、
  漏れると古いレシピが「読み込みました」と出て別の絵を描く。これは今いちばん避けたいことなので、全部一致のままにする。
  代わりにレシピへ版と commit を書き、断るときにどの版で開けば再現できるかを示す（FR-802）
- Worker の描画に時間の上限は設けない（spec の Assumptions）
- AI モデルのハッシュをビルド前に確かめる手順は、今回は入れない（モデルは手元にあり、git の外から差し替わる経路が限られるため）

## 2026-10-13 実装中に分かったこと

- 写真を替えた直後の「source N is not loaded」（FR-810）は、Phase 2 の「Worker が写真を 2 枚持つ」（FR-806）で症状が消えていた。
  Worker の部分だけを Phase 2 の前に戻すと e2e が失敗することを確かめたうえで、写真を送る場所も順番待ちの中に移した
- 写真を続けて 2 枚選ぶ e2e は、小さい画像では順番の乱れが起きず、直す前でも通った。1200 万画素の画像をテストの中で作り、失敗を再現してから直した
- 世界の記録は、はじめ別案 0・1 の 15 枚にしたが、光の形（縁）を変えても気づかなかった。別案 0〜5 の 43 枚に広げると気づいた（記録を増やした理由）
